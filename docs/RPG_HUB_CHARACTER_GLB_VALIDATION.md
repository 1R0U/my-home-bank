# キャラクターを `.glb`（リギング済み3Dモデル）へ差し替えられるかの検証

[Issue #256](https://github.com/1R0U/my-home-bank/issues/256) の段階1（検証）の記録。親は [#252](https://github.com/1R0U/my-home-bank/issues/252)。

## 結論: 今は変えない（パーツ組み立てを続ける）

技術的には差し替えられる。色替え・跳ね・着せ替えは、どれも条件つきで今の仕組みのまま成り立つ。
それでも今は変えない。理由は次の3つ。

1. **見た目で得をしない。** 固定の見下ろしカメラでは、カエル1匹が画面上で横幅およそ47px（CSSピクセル）にしかならない。細かいモデルの細部はつぶれて見えないので、この画面で映えるのは結局、今と同じ「大きな塊を組んだ形」になる。
2. **色替えを成り立たせるには、モデルを自分たちで作る必要がある。** 家族の作り分けには、色替えの枠ごとに素材を分けてあることが条件になる（下の「色替え」）。配布されているモデルはたいてい素材が1枚のテクスチャにまとまっていて、そのままでは使えない。Blender などでモデルを作り、決まりに沿って書き出す作業が毎回発生する。
3. **描画負荷の差は、`.glb` にしなくても取れる。** ドローコールが減る効果はあったが、これは素材ごとにメッシュをまとめた効果で、`.glb` 固有の利点ではない。パーツ組み立てのままでも、同じまとめ方で取れる（[docs/RPG_HUB_ARCHITECTURE.md](RPG_HUB_ARCHITECTURE.md) 8節の Thin Instances と同じ考え方）。

**見直すきっかけ**になるのは、次のどちらかが出てきたとき。

- 箱の組み合わせでは表せない動き（手足を振る歩き方など）や、丸みのある形が欲しくなった
- モデルを作って決まりどおりに書き出せる人・手段がそろった

そのときは段階2を別Issueに切り、下の「差し替えるときに必要なこと」から始める。

## 検証の方法

- WebView 内と同じ Babylon.js 9.25.0（`babylonjs` の UMD）と、glTF ローダー（`babylonjs-loaders` の `babylon.glTF2FileLoader.js`、同じ版）をブラウザ（Chromium、ソフトウェア描画）で動かした。
- カメラ・照明・地面の色は `webview/rpg-hub/scene.ts` と同じ値にした（正射影、オフセット (9, 11, 9)、`ORTHO_HALF_HEIGHT = 7.5`、環境光0.42＋平行光0.72、春の地面 `#9bd18b`）。画面は 390×844（CSSピクセル）、ピクセル比2。
- 試したモデルは3つ。
  - **カエル（検証用に作ったもの）**: `PLAYER_PARTS` と同じ形に、骨6本（胴・頭・後ろ足×2・前足×2）と跳ぶアニメ（19フレーム / 60fps ≒ 320ms、`playerMotion.ts` の1跳躍と同じ長さ）を付けて `.glb` に書き出した。素材は `slot_skin` / `slot_accent` / 固定色3つ（のど・白目・瞳）に分けた。
  - **Fox / CesiumMan**: Khronos の glTF サンプル（それぞれ CC0＋CC-BY 4.0 / CC-BY 4.0）。配布されている普通のモデルの代表として使った。
- 検証用のコードとモデルはリポジトリに入れていない。結論だけをここに残す。

## 項目ごとの結果

### 色替え（`palette`）で家族を作り分けられるか — 条件つきで成り立つ

- 1つのアセットから4人ぶん複製し、それぞれ別の色に塗り分けられた。形（ジオメトリ）は4人で共有され、素材だけが1人ずつ別になる（`instantiateModelsToScene` の `cloneMaterials: true`）。**「家族が何人いてもアセットは1つ」という前提は崩れない。**
- **ただし条件がある。** 色替えの枠ごとに素材を分け、どの素材がどの枠かを名前で分かるようにしておくこと（今回は `slot_skin` のように名付けて、名前から枠を引いた）。今の `paletteSlot` をパーツに付けているのと同じことを、モデルを作る側でやる必要がある。
- Fox も CesiumMan も素材は1つで、色は1枚のテクスチャに描かれていた。この形のモデルでは、枠ごとの色替えはできない。
- **読み込んだ素材はそのままでは使えない。** glTF の素材は PBR（`PBRMaterial`）として読み込まれ、今のシーンの照明（`StandardMaterial` 向けに、上向きの面の明るさの合計がほぼ1.0になるよう合わせてある）では目に見えて暗くなった。読み込んだあとで `StandardMaterial` に置き換えれば、パーツ版と同じ見た目になる。
  - 置き換えるときは色を**リニアからガンマに戻す**（`albedoColor.toGammaSpace()`）。glTF の色はリニアで保存されているため、そのまま移すと暗くなる。

### アニメーションと `playerMotion.ts` の跳ねが噛み合うか — 噛み合う

- **アニメは自動で再生せず、`hopPhase` からフレームを決めて止める**（`goToFrame(hopPhase / π × 最終フレーム)`）。こうすれば跳ねの位相とアニメがずれることはなく、止まっている間（`hopPhase = 0`）は基本の姿勢に戻る。自動再生にすると `playerMotion.ts` と別々の時計で動くので、二重になったりずれたりする。
- 今の上下動と伸び縮み（`HOP_STRETCH`）は、モデルを包む親ノードに掛ければそのまま使えた。骨で変形するメッシュも親ノードの伸び縮みに従う（跳ねの頂点で、体の上端が 0.77 → 1.05 に上がった）。
- 向きの追従（`facingY`）も、同じ親ノードの回転で済む。

### 着せ替えのアンカーを骨に付け替える必要があるか — 頭を動かすなら必要

- 頭の骨をわずかに（0.12ラジアン）うなずかせたとき、帽子の位置は次のようにずれた。

  | 付け方 | 着地→跳ねの頂点での移動（y / z） |
  | --- | --- |
  | 今のように体の原点に付ける（`player.anchors.head`） | +0.296 / −0.013 |
  | 頭の骨に付ける | +0.319 / −0.103 |

  差は約0.1で、帽子の直径（0.66）に対して無視できない。体の原点に付けたままだと、頭が動いたぶん帽子が頭にめり込むか浮く。
- 足だけを動かし、頭を動かさないアニメなら、今のアンカーのままでよい。
- 骨に付ける場合は、`catalog.ts` のアンカーに「どの骨に付けるか」を足し、位置を骨からの相対に直す必要がある。**着せ替え品の側（`HAT_PARTS` など）は変えなくてよい**（今の「座標はキャラクター側が持つ」という決まりのまま）。

### 描画負荷とバンドルサイズ — 増えるのは約3%、負荷は実機で未確認

**バンドルサイズ**

| 物 | 大きさ |
| --- | --- |
| 今の Babylon 本体（`assets/babylon/babylon.txt`） | 8.3MB |
| 追加で要る glTF ローダー（`babylon.glTF2FileLoader.js`） | 276KB（本体の約3.3%） |
| 検証用のカエル `.glb` | 307KB（書き出しの都合で無駄が入っている。頂点数は今のカエルと同じ3810） |
| Fox / CesiumMan | 163KB / 438KB |

WebView へは base64 にして渡すので、モデルは1.33倍になる。

**描画負荷**（ソフトウェア描画での相対比較。**実機の値ではない**）

| 数 | パーツ組み立て（中央値 / 90%値 / ドローコール） | `.glb`（同） |
| --- | --- | --- |
| 1体 | 0.6ms / 1.1ms / 24 | 0.2ms / 0.4ms / 6 |
| 12体 | 3.8ms / 6.6ms / 242 | 0.8ms / 1.6ms / 56 |
| 30体 | 7.9ms / 12.2ms / 623 | 2.0ms / 2.6ms / 141 |

- `.glb` のほうが軽く出たのは、ドローコールが1体あたり23回から5回に減ったため。`.glb` は素材ごとに1つのメッシュにまとまっている。**パーツ組み立てでも、素材ごとにメッシュをまとめれば同じ効果が出る**ので、`.glb` にする理由にはならない。骨による変形のぶんの負荷は、この数では目立たなかった。
- 実機での基準値を取る [#200](https://github.com/1R0U/my-home-bank/issues/200) がまだなので、実機での判断は保留する。家族の人数ぶんキャラを並べて重くなったら、先に「パーツを素材ごとにまとめる」ほうを試す。

### WebView への渡し方 — 今の仕組みに乗せられる

- `.glb` を base64 の data URL にして `LoadAssetContainerAsync(url, scene, { pluginExtension: ".glb" })` で読み込めた。外部へのアクセスは要らない。
- 今は `babylon.txt` と `scene.txt` を Metro のアセットとして読み、HTML に埋め込んでいる（`components/rpg-hub-web/sceneHtml.ts`）。同じやり方で、ビルド時に `.glb` を base64 にしたテキストを作って埋め込めばよい。ローダーは `scripts/sync-babylon.mjs` で本体と一緒に取り出す形にできる。
- esbuild でまとめるシーン本体（`scene.ts`）に、バイナリを入れる必要はない。

### 見下ろし正射影カメラで細かいモデルが見分けられるか — 細かいモデルは見分けにくい

- この画面では1ワールド単位が約56px（CSSピクセル）で、カエル（横幅0.84）は約47px になる。
- 同じ高さ（0.9）にそろえて並べると、Fox（1728三角形、テクスチャ付き）は輪郭と色で狐だと分かった。CesiumMan（人型、14016三角形）は細部がつぶれ、何なのか判別できなかった。
- 今のパーツ組み立てのカエルは、**大きな塊を「映る3面（上面・+X面・+Z面）」に合わせて置いている**ので、このサイズでも目・口・のどが読める。`.glb` にしても、この画面で読める形にするなら結局同じ作り方になる。

## 差し替えるときに必要なこと（段階2の出発点）

見直すきっかけが来たときのために、検証で分かった必要事項を残す。

- モデルは**色替えの枠ごとに素材を分け、名前で枠が分かるようにする**（例: `slot_skin` / `slot_accent` / `slot_hair`）。固定色の部分は別の素材にする。
- 読み込んだ素材を `StandardMaterial` に置き換える。色は `toGammaSpace()` で戻す。
- アニメは自動再生せず、`playerMotion.ts` の `hopPhase` からフレームを決める。上下動・伸び縮み・向きは今のまま親ノードに掛ける。
- 頭を動かすなら、アンカーを骨に付ける（`catalog.ts` に骨の指定を足す）。
- glTF ローダーを WebView に追加し、モデルは base64 のテキストアセットとして HTML に埋め込む。
- モデルのスケールと原点をそろえる。Fox は単位が違い、0.0118倍に縮める必要があった。書き出しの段階で「1 = 1m、足元が原点」にそろえておく。
- `npm run build:scene` は `.glb` を入れても変わらず走らせる（ローダーとモデルはシーン本体のバンドルに入らないが、シーン側の読み込み処理は入る）。
