# 着せ替え品・装飾品の購入（Issue #225）

ストアは「商品」「きせかえ」「かざり」の棚に分ける。着せ替え品10種類・装飾品19種類は、家庭の金庫作成時に全種類を無制限在庫で自動陳列する。既存家庭にもSQLで補完する。親が追加・価格設定するのは通常商品だけで、商品追加申請も従来どおり使える。

アセットの基準価格は全品共通で、金庫の初期供給量 `initial_supply` の0.5%を四捨五入し、最低1 golとする。初期金庫10,000 golなら50 gol、20,000 golなら100 gol。現在の残高や追加発行額では変えない。実売価格には既存の月次物価指数を反映する。

着せ替え品は1人1種類1個まで。装飾品は複数購入でき、所有総数から配置済み数を引いた数だけ置ける。しまっても所有は失わず、再び配置できる。以前から持っている着せ替え品と配置済みの装飾は保持する。装飾の追加購入は子供の既存の購入フローを使う。

価格・在庫・決済は既存の `purchase_store_item` に任せ、経済台帳の新規購入行を契機に同じDBトランザクションで所有へ加える。所有付与が失敗すれば送金・在庫・両台帳も取り消される。同じ操作IDの再送は同じ取引を返し、所有を増やさない。異なる操作IDでも、所有済みの着せ替えは拒否する。

装飾の配置はDBトリガーで所有行をロックし、別端末から同時に置いても購入数を超えないよう検査する。利用者は所有数・販売カタログを直接変更できない。

## 本番への反映

次の3本を順番に適用する。SQL Editorを使う場合は、配置操作を止め、3本の内容を1つの `BEGIN` / `COMMIT` で実行すると、旧アプリの配置が補完と保護の間に入り込むことを避けられる。ファイル名だけをSQLとして実行しない。

1. `20261011072555_add_store_asset_ownership.sql`：販売カタログ、商品との紐付け、所有数を追加。
2. `20261011072556_backfill_owned_decorations.sql`：配置済み装飾を、その数だけ所有として引き継ぐ。未知のアセットがあれば推測で補正せず停止する。
3. `20261011072557_connect_store_purchases_to_ownership.sql`：購入時の付与、配置数の保護、商品一覧の所有数を追加。

上の3本をすでに適用済みの環境は再実行せず、以下の3本を順に適用する。SQL Editorでは同じく1つの `BEGIN` / `COMMIT` にまとめる。

4. `20261011113829_add_automatic_store_asset_columns.sql`：自動商品・商品名の列、重複防止、親の登録制限。
5. `20261011113831_configure_automatic_store_assets.sql`：商品名・価格計算・新規家庭の自動陳列。
6. `20261011113832_backfill_automatic_store_assets.sql`：既存家庭へ全種類を補完。手動販売した旧アセットは削除せず販売停止にし、購入履歴・所有・通常商品を保持する。

自動陳列の追加では大量のお知らせを作らない。新しい販売アセットは新規SQLで `store_assets` にID・種別・商品名を追加し、全家庭で `private.seed_family_store_assets` を実行して補完する。新規家庭もこのカタログを使う。

その後 `tests/sql/verify_remote_schema.sql` が全行OKになることを確認する。SQL Editorでの実行とCLIの適用履歴は別なので、CLIを併用する場合は履歴も照合する。新しいEdge Functionや環境変数は不要。

## 実機確認

- 親が商品登録をしなくても、子供の棚に着せ替え品10種類・装飾品19種類が並ぶ。
- 初期金庫10,000 golなら基準価格50 gol。親の管理フォームは通常商品だけを追加できる。
- 子供の対応する棚だけに商品が表示され、通常商品は「商品」の棚に残る。
- 着せ替え品を購入し、更衣室で装備できる。同じ品の再購入は「持っています」で止まる。
- 装飾を2個購入し、2個置ける。3個目は置けず、1個しまえば再び置ける。
- 残高不足で購入できず、残高・在庫・所有が変わらない。
- 既存の配置・着せ替えと通常商品の購入が引き続き使える。

新しい販売アセットを増やす際は、見た目を `lib/rpg-hub/catalog.ts` に追加し、新規マイグレーションで `store_assets` にID・種別・商品名を追加して既存家庭を補完する。既存マイグレーションを書き換えない。DBとアプリの許可リスト・商品名の一致は `tests/storeAssets.test.mjs` で確認する。
